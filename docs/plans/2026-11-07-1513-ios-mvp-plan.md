# Native iOS MVP Plan

## Goal

Deliver a simple native SwiftUI client that connects to one self-hosted CastDock server and completes the Inbox → Up Next → playback workflow using the same canonical backend state and HTTP contracts as the web player.

## Product Contract

- A setup screen stores the server URL and optional credentials in Keychain and reconnects automatically.
- Inbox and Up Next use JSON endpoints backed by the same repositories and state transitions as the web UI.
- Users can queue, archive, mark played, reorder Up Next, and open an episode player.
- AVPlayer streams publisher audio, applies feed playback speed, seeks ±15 seconds, syncs every five seconds and on lifecycle events, and supports background/lock-screen controls.
- Credentials never enter source, UserDefaults, logs, or analytics. HTTP is supported for private self-hosting but the app warns that HTTPS is preferred.
- Library, Archive, Recent Published, Play History, OPML, and subscription management remain outside this milestone.

## Acceptance Evidence

- Server JSON contract tests cover home data, episode detail, lifecycle actions, and authentication.
- Swift unit tests cover URL normalization, decoding, and Keychain-facing configuration behavior.
- The app builds, installs, and launches on an available iPhone simulator.
- Setup and empty/error/loading states render without crashes; live server behavior remains a human verification when the simulator cannot reach the user's private server.

## Validation Result

- Go API, OpenAPI, authentication, lifecycle and playback tests pass, including race detection.
- The Xcode project builds successfully for the iPhone 18 Pro simulator on Xcode 27.2.
- Three Swift unit tests pass for server URL normalization and shared API decoding.
- The app installs and launches in the simulator; the setup screen was visually verified.
- Live private-server login, streaming, background audio and lock-screen behavior remain human verification because XcodeBuildMCP is not connected to this agent harness.
